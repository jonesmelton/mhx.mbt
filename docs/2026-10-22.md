## 実装メモ

`docs/ffi-boundary.md` は element identity を FFI の DOM read の責務としている。`ConfigCache::get_element_id` のコメントも JS 側での element tracking を前提にしているので、key の払い出しは FFI 側に置いた。

`data-*` 属性に key を書く方法も考えたが、利用者の DOM に mhx の内部状態が見えてしまうので採らなかった。`WeakMap` なら DOM を変更せず、外れた element を保持し続けることもない。

`hash_element` という名前は呼び出し箇所が多いので残した。実体はもう hash ではないが、今回は bug fix に絞る。

## 計画: delayed trigger element

`issues/2026-10-22T095755-bug-delayed-trigger-loses-element.md` に対応する。
`delay` / `throttle` / `debounce` 付きの trigger が、match した element ではなく DOM walk が最後に到達した element で実行されるので、callback に渡す element を固定する。

- `Mhx::handle_event` で match 時点の `current` を `element` に束縛する。
- timing modifier の callback と即時実行の両方で `element` を使う。
- issue を `issues/closed/` に移動し、解決方法を書く。

## 実装メモ: delayed trigger element

MoonBit の closure は `let mut` の変数を値ではなく変数として capture する。`apply_timing_modifiers` に渡した callback は timer が発火した時点の `current` を読むので、walk の続きで親へ進んだ後の値になっていた。即時実行の経路は同じ iteration 内で呼ばれるので壊れていなかったが、どちらも同じ `element` を使う形に揃えた。
