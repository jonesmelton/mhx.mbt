# 2026-10-22

## 計画

`issues/2026-10-22T095754-bug-element-cache-key-collision.md` に対応する。
id を持たない同じ tag の element が config cache の key を共有してしまうので、element reference ごとの key に置き換える。

- `src/ffi/mhx_ffi.js` に `WeakMap` で key を払い出す `element_key` を追加する。
- `src/ffi/element.mbt` に `Element::key` を追加し、`hash_element` はそれを返すだけにする。
- `npm/smoke/` に element key の contract test を追加する。
- issue を `issues/closed/` に移動し、解決方法を書く。

## 実装メモ

`docs/ffi-boundary.md` は element identity を FFI の DOM read の責務としている。`ConfigCache::get_element_id` のコメントも JS 側での element tracking を前提にしているので、key の払い出しは FFI 側に置いた。

`data-*` 属性に key を書く方法も考えたが、利用者の DOM に mhx の内部状態が見えてしまうので採らなかった。`WeakMap` なら DOM を変更せず、外れた element を保持し続けることもない。

`hash_element` という名前は呼び出し箇所が多いので残した。実体はもう hash ではないが、今回は bug fix に絞る。

## 検証

`main` は現在の toolchain (`moon 0.1.20261020`) では `moon.mod.json` を読めず build できない。`.tool-versions` の `0.1.20260409` は配布元から取得できなかったので、commit しない local の作業として `moon.mod` への移行、`moonbitlang/async` を 0.22.5 にする変更、移行済みの `mhx-spec` 0.1.1 を workspace に置く変更、test 2 箇所の `try?` の置き換えをして確認した。

- `node --test npm/smoke/*.test.mjs`: 成功。11 tests passed。追加した 2 tests は修正前に `element_key` が無いため失敗することを確認した。
- `moon test --target js`: 26 / 27 passed。失敗する `src/event/trigger_golden_test.mbt:212` は修正前から同じで、新しい toolchain の `Debug` 出力形式の差による。
- browser での再現: issue の HTML を `npm/postbuild.mjs` と `vite build` で作った `dist/mhx.umd.js` で開き、2 つ目の link が `GET /a` ではなく `GET /b` を送ることを確認した。
